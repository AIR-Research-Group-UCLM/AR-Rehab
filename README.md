# RehabSensorsData — Raw session logs for occlusion-resilient Mixed Reality upper-limb rehabilitation

This repository contains the **raw, per-session data logs** generated by an
occlusion-resilient hybrid **visuo-inertial smart object** system for upper-limb
neurorehabilitation in **Mixed Reality (MR)**. Therapeutic cubes (Box-and-Block-Test
style) were instrumented with a low-power embedded board (Seeed Studio XIAO
nRF52840 Sense) carrying a 6-axis IMU and a Force Sensing Resistor (FSR). Their
telemetry is streamed over Bluetooth Low Energy (BLE) to a **Meta Quest 3**,
where it is fused with on-device YOLOv8-Pose object detection and native hand
tracking to keep a virtual *digital twin* aligned with the real cube — even when
the patient's hand fully occludes it.

The data here were recorded during a **preliminary feasibility evaluation at the
Hospital Nacional de Parapléjicos (Toledo, Spain)** with six participants
(two spinal-cord-injury patients, two clinical/technical professionals, and two
participants with no known motor impairment). The logs are released so that the
tracking pipeline, the fusion behaviour, and the functional/kinematic metrics can
be inspected, reproduced, and re-analysed.

> **At a glance — what makes this data useful.** Each session contains
> synchronized streams of (i) raw IMU + grip telemetry, (ii) on-device visual
> detections with keypoints, (iii) the fused 6-DoF pose of the digital twin,
> (iv) full patient head/hands kinematics, (v) automatically segmented
> manipulation events, (vi) serious-game events, and (vii) the yaw-calibration
> log. Together they allow a frame-by-frame reconstruction of how the system
> tracked each object and how each participant performed.

## Repository structure

```
RehabSensorsData/
├── Patient1/  , Patient2/         # SCI patients
├── Therapist1/, Therapist2/       # clinical / biomedical professionals
├── Person1/   , Person2/          # participants without known motor impairment
│   └── SESSION_<yyyyMMdd>_<HHmmss>_R<k>_RH/ # one folder per recorded round
│       ├── sensor_imu.csv
│       ├── vision_data.csv
│       ├── vision_data_all.csv
│       ├── fusion_result.csv
│       ├── cube_state.csv
│       ├── patient_kinematics.csv
│       ├── interaction_segments.csv
│       ├── game_events.csv
│       └── calibration_log.csv
```

**Session folder name** — `SESSION_<date>_<time>_R<k>_RH`:
`<date>`/`<time>` is the capture timestamp, `R<k>` is the round number, and
`RH` denotes the **right hand** (the hand used in all sessions). Each round
comprises 10 targets of the serious game.

**`tracker_id`** identifies the physical smart object. Inertial/fusion logs use
`CubeRed` / `CubeBlue`; the vision logs may use the short colour form
(`Red` / `Blue`). Each colour maps deterministically to one BLE device.

## Conventions (read this first)

- **Coordinate frame:** Unity world frame (left-handed, Y up). Positions are in
  **metres**; the headset/play area defines the origin.
- **Orientations:** unit quaternions `(x, y, z, w)`; Euler angles, when present,
  are in **degrees**.
- **Linear velocity:** metres per second (`m/s`); **angular velocity:** degrees
  per second (`deg/s`).
- **Time:** `time_s` is seconds from the start of the session (per file).
- **Sampling:** IMU/orientation telemetry ≈ 33 Hz, FSR ≈ 10 Hz, on-device vision
  ≈ 5 Hz, per-frame state at the headset frame rate; streams are logged
  asynchronously, so timestamps (not row indices) must be used to align them.
- **`raw_grip`:** offset-corrected FSR analog reading (ADC counts; higher = more
  pressure). It is a relative pressure proxy, not a calibrated force in newtons.

## File-by-file variable reference

### `sensor_imu.csv` — raw smart-object telemetry (as received over BLE)
| Column | Description | Unit |
|---|---|---|
| `time_s` | Timestamp from session start | s |
| `tracker_id` | Smart object identity | — |
| `qx, qy, qz, qw` | Object orientation quaternion (sensor fused on-device, Madgwick) | — |
| `raw_grip` | FSR pressure reading (offset-corrected) | ADC counts |

### `vision_data.csv` / `vision_data_all.csv` — on-device YOLOv8-Pose detections
`vision_data.csv` holds the **filtered/accepted** detections used by the system;
`vision_data_all.csv` is the **raw detection stream** (everything the detector
emitted, useful for debugging and full replay).
| Column | Description | Unit |
|---|---|---|
| `time_s` | Timestamp | s |
| `tracker_id` | Detected object (colour) | — |
| `bbox_x, bbox_y` | Bounding-box top-left position in the camera image | px |
| `bbox_w, bbox_h` | Bounding-box width / height | px |
| `bbox_score` | Detection confidence (0–1) | — |
| `kp{0..3}_x, kp{0..3}_y` | The four top-face keypoints (cube vertices), image coords | px |
| `kp{0..3}_v` | Per-keypoint visibility/confidence (0–1) | — |
| `calib_status` | Yaw-calibration state at that detection (`ongoing`, `initial`, `post_release`, …) | — |

### `fusion_result.csv` — fused pose delivered to the application (compact)
| Column | Description | Unit |
|---|---|---|
| `time_s` | Timestamp | s |
| `tracker_id` | Object | — |
| `pos_x, pos_y, pos_z` | Fused digital-twin position | m |
| `rot_y` | Fused horizontal orientation (yaw) | deg |
| `is_gripping` | FSR-confirmed grasp active (0/1) | bool |
| `down_face_x/y/z` | Unit vector of the cube face locked downward (resting pose) | — |

### `cube_state.csv` — full per-frame state of each object (richest stream)
| Column | Description | Unit |
|---|---|---|
| `time_s` | Timestamp | s |
| `tracker_id` | Object | — |
| `pos_x, pos_y, pos_z` | Digital-twin position | m |
| `rot_x, rot_y, rot_z, rot_w` | Digital-twin orientation quaternion | — |
| `euler_x, euler_y, euler_z` | Same orientation as Euler angles | deg |
| `vel_x, vel_y, vel_z` | Linear velocity components | m/s |
| `speed_mps` | Linear speed magnitude | m/s |
| `ang_vel_deg_s` | Angular speed magnitude | deg/s |
| `is_gripping` | FSR-confirmed grasp active (0/1) | bool |
| `grip_source` | Active tracking source: `fsr`, `imu_bridge`, or `none` | — |
| `contact_level` | Multimodal contact state (see enum below) | — |
| `raw_grip` | FSR pressure reading | ADC counts |
| `imu_delta_deg` | Inter-frame IMU angular change (motion indicator) | deg |
| `down_face_x/y/z` | Unit vector of the downward-locked face | — |

### `patient_kinematics.csv` — head and hands (native Meta SDK tracking)
| Column | Description | Unit |
|---|---|---|
| `time_s` | Timestamp | s |
| `head_px/py/pz`, `head_rx/ry/rz/rw` | Head position / orientation | m, quat |
| `handR_px/py/pz`, `handR_rx/ry/rz/rw` | Right-hand position / orientation | m, quat |
| `handL_px/py/pz`, `handL_rx/ry/rz/rw` | Left-hand position / orientation (0 if not tracked) | m, quat |
| `gaze_x, gaze_y, gaze_z` | Gaze direction unit vector | — |

### `interaction_segments.csv` — automatic manipulation segments
One row per detected grasp→release interaction (segmented from the FSR transitions).
| Column | Description | Unit |
|---|---|---|
| `start_time_s, end_time_s` | Segment bounds | s |
| `duration_s` | Segment duration | s |
| `tracker_id` | Manipulated object | — |
| `start_x/y/z`, `end_x/y/z` | Object position at grasp / release | m |
| `path_length_m` | Accumulated trajectory length during the segment | m |
| `avg_speed_mps`, `max_speed_mps` | Mean / peak speed in the segment | m/s |
| `release_type` | `placement`, `drop`, or `release` (see enum below) | — |
| `final_contact_level` | Contact level at segment end | — |

### `game_events.csv` — serious-game events
| Column | Description |
|---|---|
| `time_s` | Timestamp (s) |
| `event_type` | `RoundStart`, correct/incorrect placement, `Timeout`, game end, … |
| `round` | Round number |
| `score`, `hits`, `misses`, `combo`, `best_combo` | Running game scoring |
| `expected_color`, `placed_color` | Target colour vs. the colour actually placed |
| `details` | Free-text detail (e.g. `round=3 countdown=20s`) |

### `calibration_log.csv` — marker-free yaw calibration events
One row each time the 6-axis IMU yaw drift is corrected against the visual keypoints.
| Column | Description | Unit |
|---|---|---|
| `time_s` | Timestamp | s |
| `tracker_id` | Object | — |
| `path` | Calibration path: `initial_keypoint_yaw`, `post_release_keypoint_yaw`, `continuous_keypoint_yaw` | — |
| `raw_offset_deg` | Raw yaw offset applied | deg |
| `abs_error_deg` | Absolute angular error before correction | deg |
| `sym_error_deg` | Error after accounting for the cube's 90° symmetry | deg |
| `calib_type` | `instant` (applied at once) or `smooth` (interpolated) | — |

## Enumerations

**`contact_level`** (multimodal hand–object contact model):
| Value | Meaning |
|---|---|
| `Resting` | Object on the table, hand away |
| `Nearby` | Hand close, no contact evidence |
| `Touching` | Hand over the object (visual match) |
| `HeldSoft` | Probable hold inferred without FSR pressure (hand proximity + inertial motion + vision) |
| `HeldHard` | FSR-confirmed grasp |

**`grip_source`** (which mechanism is driving the pose):
| Value | Meaning |
|---|---|
| `none` | Surface state (visual position + calibrated IMU orientation) |
| `fsr` | Pressure-confirmed grasp: object anchored to the hand transform |
| `imu_bridge` | Hand-anchored inertial occlusion bridge: continuity preserved under occlusion without FSR pressure |

**`release_type`** (how a segment ended):
| Value | Criterion |
|---|---|
| `placement` | Controlled release (low speed, surface contact) — deliberate placement |
| `drop` | High release speed — abrupt drop |
| `release` | Generic release meeting neither criterion |

## Suggested analyses

- **Tracking-source utilisation:** the share of in-contact frames sustained by
  `imu_bridge` vs. `fsr` quantifies how much the occlusion bridge contributes in
  real use (per participant via `cube_state.csv`).
- **Contact-model behaviour:** ratio of `HeldSoft` to `HeldHard` shows how many
  grasps are captured without FSR pressure.
- **Drift / registration accuracy:** distribution of `sym_error_deg` per
  calibration `path` (`calibration_log.csv`).
- **Detection quality:** detection rate, bounding-box freshness, and keypoint
  visibility from `vision_data.csv`.
- **Functional / kinematic performance:** game outcomes (`game_events.csv`),
  trajectory length, speed, and head/hand ratios (`patient_kinematics.csv`),
  and per-grasp metrics (`interaction_segments.csv`).

## Notes and caveats

- This is a **preliminary feasibility** dataset (6 participants); it is intended
  for technical reproducibility and exploratory analysis, **not** for inferential
  clinical conclusions.
- Streams are logged asynchronously at different rates — **align by `time_s`**,
  not by row index.
- Some `interaction_segments.csv` rows can be very short (brief FSR transitions);
  treat the segment file as a secondary source and cross-check with `cube_state.csv`.
